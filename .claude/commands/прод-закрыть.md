Выполни полный цикл выкатки и закрой ветку/сессию.

1. **Ревью.** Запусти `/code-review high` по текущему диффу.
2. **Исправления.** Исправь все найденные проблемы.
3. **Повторный ревью.** Снова запусти `/code-review high`. Повторяй шаги
   2–3 (правки → ревью) до тех пор, пока ревью не вернётся **без замечаний**.
   Не выходи из цикла раньше: каждая итерация правок обязана завершаться новым
   прогоном ревью.
4. **Проверка сборки.** Убедись, что `npm run build` зелёный (`tsc -b` обязан
   проходить — иначе деплой на Vercel молча падает).
5. **Деплой на прод — всегда из `main`, чтобы не перезатереть чужие деплои.**
   Прод собирается из актуального `main`, чтобы в него попали ВСЕ уже влитые
   чужие изменения + **только твоя правка из этой сессии**, а не голый снимок
   ветки (иначе прод откатится и потеряет чужую работу). Никогда не деплой на
   прод из отставшей от `main` ветки как есть.
   1. `git fetch origin` — подтяни актуальное состояние.
   2. Закоммить правку сессии, если ещё не закоммичено
      (`mcp__nimbalyst__developer_git_commit_proposal`).
   3. Заведи правку в `main` поверх свежего `origin/main`:
      - в ветке: `git rebase origin/main` (разреши конфликты, ничего не теряя),
        затем `git switch main`, `git pull --ff-only origin main`,
        `git merge --ff-only <ветка>` и `git push origin main`;
      - прямо в `main`: `git pull --rebase origin main`, затем `git push`.
      Если fast-forward невозможен или есть риск потерять чужие/свои изменения —
      остановись и спроси меня.
   4. Пересобери из актуального `main`: `npm run build` — зелёный (`tsc -b`
      обязан пройти).
   5. Деплой из `main`: `npx vercel --prod`.
   6. **Сверься по СОДЕРЖИМОМУ бандла, а не по имени** (удалённая сборка даёт
      другой хэш имени файла). Дождись обновления прода и грепни задеплоенный
      бандл на уникальный литерал из твоей правки (минификатор может срезать
      ведущий `0` — ищи устойчивый фрагмент). Если литерала нет — значит
      параллельный поздний деплой перезаписал прод: передеплой
      `npx vercel --prod` из `main` и проверь снова. Дополнительно сверься
      `vercel inspect`.

После успешного деплоя твоя правка уже влита в `main` и лежит в проде.
Закрой работу:

6. **Удалить ветку.** Ветка влита в `main` ещё на шаге 5. Если она больше не
   нужна — удали её локально (`git branch -d <ветка>`) и на remote
   (`git push origin --delete <ветка>`). Ничего не теряй; если ветка не влилась
   fast-forward или остались незакрытые изменения — остановись и спроси меня.
7. **Архивировать сессию.** Обнови метаданные сессии: фаза `complete`, тег
   `committed` вместо `uncommitted` (`mcp__nimbalyst__update_session_meta`).
8. **Итог.** Коротко отчитайся: что задеплоено (ссылка/URL прода), что слито в
   `main` и что заархивировано.

Если на шаге 3 ревью застрял на одной и той же проблеме две итерации подряд,
правка спорная, или при заливке в `main` / удалении ветки есть конфликт/риск
потерять изменения — остановись и спроси меня, прежде чем продолжать.
