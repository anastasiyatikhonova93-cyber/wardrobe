# Пайплайн фото и доска гардероба

## Добавление фото — `useAutoIngest`

`src/hooks/useAutoIngest.ts` оркестрирует превращение «сырого» фото (файл или ссылка)
в гардеробную карточку. Источник — `{ file?, url? }`; для ссылки сначала пробуем
скачать байты (`urlToFile`), при CORS-блокировке оставляем исходную ссылку, но вещь
всё равно распознаём (картинку забирает сервер/LLM).

Порядок шагов важен:

### 1. Классификация — `src/lib/classify-photo.ts`

Категорию определяем **первой**, потому что от неё зависит промт коррекции
(одежда / обувь / сумка / аксессуар обрабатываются по-разному).

Цепочка фолбэков (`classifyPhoto` для файла, `classifyImageUrl` для ссылки):

1. **Сервер-Gemini** `/api/classify` — самый надёжный путь (см. [ai.md](ai.md)).
2. **llm7 vision** (`requestVision`) — прямой vision-запрос из браузера.
3. **Разбор имени файла** (`classifyWithFilename`) — чистит имя, прогоняет через
   `inferItemDetails`. Камерные имена (`IMG_0452`, `DSC0001`, `screenshot`, `снимок`…)
   распознаются `isCameraFilename` и отбрасываются — лучше пусто, чем «IMG 0452».

Перед отправкой файл ужимается до компактного JPEG (`fileToCompactDataUrl`,
`maxDim 1024`) — у Vercel-функции лимит тела ~4.5 МБ. Результат валидируется
(`validateCategory` / `validateSeasons`), `confidence` помечается `vision`/`filename`/`default`.

### 2. Коррекция фото — `src/lib/photo-cleanup.ts`

Две стратегии, лучшая выбирается с откатом:

- **`cleanupBest`** (предпочтительно): `cleanupPhotoAI` (Gemini-ретушь на чистый
  белый фон) → `removeBackground` (вырезание этого фона в прозрачный PNG). Фон после
  Gemini ровный и однотонный, поэтому вырезание без ореола.
- **`cleanupPhoto`** (фолбэк, если AI недоступен): локальное вырезание фона
  `@imgly/background-removal` (в браузере, бесплатно, прозрачный PNG) → `enhance`
  (авто-цветокоррекция).

`useAutoIngest` пробует `cleanupBest`, при ошибке — `cleanupPhoto`, при ошибке и
там — оставляет фото как есть (процесс не валится).

**`api/clean-image.ts`** (Gemini image-gen): промт выбирается по категории
(`promptForCategory` → `clothing` / `shoes` / `bags` / `accessory`) + общий хвост
`COMMON` с требованиями (убрать человека/руки/кожу, не менять цвет и пропорции вещи,
чистый белый фон #FFFFFF, e-commerce качество). Промт `clothing` дополнительно
просит вещи с передней застёжкой (пиджак, блейзер, плащ, тренч, кардиган, рубашка,
блузка) показывать **расстёгнутыми** — полы распахнуты симметрично, подкладка
частично видна; вещи без застёжки спереди (платья, футболки, свитера, брюки, юбки)
не трогать. **Требует биллинга Google**: без него 429 → откат на локальную обработку.
Это известное ограничение, см. memory `gemini-photo-cleanup`.

**`autoColorCorrect`** (локальная коррекция «как в онлайн-магазине»): авто-контраст
растяжением яркости по перцентилям (`LOW_PCT 0.5%` / `HIGH_PCT 99.5%`) + лёгкое
поднятие насыщенности (`SATURATION 1.14`). Работает только по непрозрачным пикселям,
альфа сохраняется; единый линейный сдвиг по каналам — баланс белого не «уезжает».

**`removeBackground`** (`src/lib/background-removal.ts`): тонкая обёртка над
`@imgly/background-removal` с **ленивой загрузкой** модуля (тяжёлая модель грузится
по требованию; `preloadModel` для прогрева).

### 3. Сжатие и сохранение — `src/lib/storage.ts`

`uploadPhoto` → `compressToDataUrl` ужимает результат под лимит документа Firestore
(`MAX_DATA_URL` ≈ 900 КБ) и возвращает data-URL, который пишется инлайн в документ
вещи. Детали кодирования (WebP/PNG/JPEG) — в [data-model.md](data-model.md).

## Массовый импорт (фоновый) — `src/lib/importStore.ts` + `ImportPage`

Страница `/import` (`src/pages/ImportPage.tsx`) — пакетная загрузка многих фото за
раз. Три шага: `select` (выбор файлов) → `process` (обработка) → `review` (правка
полей и сохранение пачкой через `addClothingBatch`).

Ключевое: **обработка фоновая и не зависит от смонтированности страницы.** Всё
состояние импорта живёт в глобальном Zustand-сторе `useImportStore` (не в
компоненте), а сам движок — это действие стора `startProcessing(uid)`, а не функция
внутри `ImportPage`:

- по тапу «Начать обработку» компонент лишь вызывает `startProcessing(user.uid)`;
  дальше цикл крутится сам и пишет прогресс прямо в стор. Можно уйти на любую
  вкладку — обработка продолжается; при возврате на `/import` виден актуальный статус.
- каждый элемент проходит тот же конвейер, что и одиночный (`classifyPhoto` →
  `cleanupBest`/`removeBackground` → `uploadPhoto`), параллелизм — `processQueue`
  с concurrency 2. По одному фото на ошибку процесс не валится (статус `error`),
  повторный `startProcessing` берёт всё ещё не обработанное (`pending` + `error`).
- по завершении стор сам переводит шаг в `review`.

Глобальная индикация — `src/components/ImportProgressBadge.tsx`, отрисованный в
`Layout` (виден на всех вкладках, кроме самого `/import`): плавающая «таблетка» над
нижней навигацией показывает «Обрабатываю N из M…» или «Импорт готов — проверьте»,
по тапу возвращает в импорт. Там же (в `Layout`, а не в `ImportPage`) живёт защита
`beforeunload`: пока есть необработанные/несохранённые вещи, перезагрузка вкладки
предупреждает — иначе потеряются обработанные, но ещё не сохранённые в Firestore
результаты (`File`-объекты в памяти не переживают reload).

## Мульти-распознавание — `src/lib/detect-items.ts` + `DetectTestPage`

Разбор ОДНОГО фото (зеркальное селфи / фото образа) на НЕСКОЛЬКО отдельных вещей —
в отличие от `useAutoIngest`/`classify-photo`, которые исходят из «одна вещь на
фото». Паритет с конкурентом Tidy («распознаёт вещи даже на селфи в зеркале»).
Страница `/detect-test` (`src/pages/DetectTestPage.tsx`), публичная — рендерится до
auth-гейта, но сохранение в гардероб требует входа.

- **`detectItems(file)`** ужимает фото → `POST /api/detect` (Gemini vision, рамки
  `box_2d`, см. [ai.md](ai.md)) → нормализует рамки `0..1000 → 0..1`, валидирует
  координаты/категорию/сезоны. Сезоны от модели необязательны (пусто — дозаполнит
  пользователь).
- **`cropItem(img, box)`** вырезает каждую вещь из оригинала (не из ужатой копии)
  в PNG c небольшим паддингом.
- Дальше — флоу как у массового импорта: редактируемые карточки (название/категория/
  цвет/сезон, «убрать лишнее» — например раму зеркала, если промт всё же её поймал)
  → по каждой оставленной `cleanupBest` (фолбэк `cleanupPhoto`) → `uploadPhoto` →
  `addClothingBatch` → переход в `/wardrobe`.

## Доска гардероба — `src/lib/board-layout.ts`

Раскладывает весь гардероб на один холст-картинку.

- **`prepareItem`** — для каждой вещи делает прозрачную обрезанную картинку
  (`makeTransparent` из `transparent-image.ts`: убирает бело-серый фон порогами по
  RGB, обрезает по bounding-box непрозрачных пикселей, работает на уменьшенной до
  512px копии ради скорости, кэширует результат по `src`).
- **`computeBoardLayout`** — группирует вещи по категориям рядами в фиксированном
  порядке `ORDER` (верхняя → трикотаж → верх → платья → низ → сумки → обувь →
  аксессуары); внутри ряда пакует слева-направо с переносом и центрированием;
  высота ряда — из `ROW_HEIGHT[category]`, ширина вещи — по реальному соотношению
  сторон. «Неожиданные» категории добавляются после известных, чтобы ни одна вещь
  не потерялась.
- **`renderBoardToPng`** — рисует на canvas и отдаёт PNG. Аккуратно понижает масштаб
  под лимиты canvas в iOS Safari (`MAX_SIDE 8192`, `MAX_AREA 16M`), иначе при большом
  гардеробе можно получить пустой/чёрный PNG.

Связанные страницы UI: `WardrobeBoard` (компонент), `FixPhotosPage` (массовая
переобработка фото), `ImportPage` (импорт), `SeedPage` (демо-данные).

## Раскладка образа — `src/lib/outfit-layout.ts`

Единая геометрия для редактора (`OutfitEditor`), превью-карточки (`OutfitPreview`)
и выгрузки образов в PNG (`outfit-board.ts`) — чтобы все три совпадали.

- Размер вещи задаётся **шириной по категории** (`CATEGORY_WIDTH`, доля ширины
  холста «footprint»; верхняя/платья самые широкие, топы уже низа, обувь/сумки
  мельче) × ручным множителем `userScale`; высота выводится из ширины и реального
  соотношения сторон (`itemBoxFrac`: `hFrac=wFrac/a'`, где `a'=aspect/CANVAS_ASPECT`).
  В плоской раскладке размер читается прежде всего по ширине, поэтому фиксируем её:
  топ гарантированно не шире низа, как бы криво/широко его ни сняли (площадь-по-
  категории это не лечила — квадратный топ-запах выходил шире узких штанов). Для фото
  с «нормальным» аспектом ≈3:4 размеры почти не меняются. Аспект клампится в `[0.3, 3.2]`
  (страховка от кривого bbox), высота — потолком `0.62` (при срабатывании ужимается и
  ширина тем же коэффициентом).
- Реальные пропорции картинок измеряются на результате `makeTransparent` и кэшируются;
  на клиенте — через хук `useAspectRatios` (`src/lib/use-image-aspect.ts`), в PNG —
  пред-загрузкой картинок перед `computeBounds`.
- `computeBounds` считает bounding box раскладки (для авто-вписывания/центрирования
  в превью и PNG); редактор показывает сырые `x/y` без центрирования.
- В редакторе у каждой вещи угловой маркер `Maximize2` — тянешь за угол, меняется
  `userScale` (кламп 0.4–2.5×); противоположный угол — кнопка удаления.
